2. Arquivo assetService.js e CoinGecko

O arquivo src/services/assetService.js não foi localizado. Também não foram encontradas as funções fetchCoinGeckoData ou qualquer chamada para api.coingecko.com.

Consequentemente, o código atual:

  • não busca o ID bitcoin;
  • não utiliza o símbolo btc;
  • não envia vs_currency=brl;
  • não transforma a resposta CoinGecko em dados de ativo.

Para Bitcoin, uma implementação CoinGecko normalmente usaria o ID de mercado bitcoin, e não o ticker btc:

https://api.coingecko.com/api/v3/simple/price?ids=bitcoin&vs_currencies=brl

O parâmetro ids identifica o ativo na CoinGecko. O parâmetro vs_currencies=brl determina que o preço seja retornado em reais.

3. Dispatcher fetchAssetData

A função fetchAssetData não existe. Portanto, não há dispatcher central interceptando o ativo e roteando-o por tipo.

O fluxo real de atualização individual é:

Usuário solicita atualização
        ↓
useUpdateQuotes
        ↓
fetchBrapiAssetData(asset.ticker)
        ↓
Brapi API

O hook useUpdateQuotes chama diretamente a Brapi, sem verificar asset.type. Assim, criptomoedas, ações americanas e REITs também seriam encaminhados para a Brapi nesse caminho.

4. Implementação atual da Brapi

Em brapiService.js, fetchBrapiAssetData(ticker) busca os fundamentos do ticker, localiza o resultado correspondente e normaliza os dados para o formato interno:

{
  price,
  dividendYield,
  pL,
  pVp,
  roe,
  lpa,
  vpa,
  growthRate,
  roic,
  divEbitda
}

A URL da Brapi é montada com o ticker no caminho e, quando existe uma chave, com o token na query string:

https://brapi.dev/api/quote/{ticker}?token={chave}

Também existe uma filtragem em updateAssetPrices usando os tipos:

new Set(['Ação BR', 'FII', 'ETF', 'BDR'])

Essa filtragem não é aplicada no fluxo individual usado por useUpdateQuotes, que chama a Brapi diretamente.

5. Persistência das chaves

As chaves são definidas em src/constants/config.js:

BRAPI_API_KEY: 'goes_compra_certa_brapi_api_key'
COINGECKO_API_KEY: 'goes_compra_certa_coingecko_api_key'
ALPHA_VANTAGE_API_KEY: 'goes_compra_certa_alpha_vantage_api_key'

O componente UserSettingsPage inicializa os estados chamando os respectivos métodos .get():

const [brapiApiKey, setBrapiApiKey] = useState(() => brapiApiKeyStorage.get());
const [coinGeckoApiKey, setCoinGeckoApiKey] = useState(() => coinGeckoApiKeyStorage.get());
const [alphaVantageApiKey, setAlphaVantageApiKey] = useState(() => alphaVantageApiKeyStorage.get());

Ao salvar o formulário, as três chaves são persistidas conjuntamente:

brapiApiKeyStorage.set(brapiApiKey);
coinGeckoApiKeyStorage.set(coinGeckoApiKey);
alphaVantageApiKeyStorage.set(alphaVantageApiKey);

6. Comportamento do storageService

Brapi

brapiApiKeyStorage.get() executa localStorage.getItem(STORAGE_KEYS.BRAPI_API_KEY) e retorna string vazia quando não há valor ou ocorre erro.

CoinGecko e Alpha Vantage

Ambos usam a fábrica createApiKeyStorage(storageKey, providerName). O método get() lê a chave configurada e retorna '' como fallback.

O método set() converte o valor para string, aplica trim() e:

  • salva no localStorage se houver conteúdo;
  • remove a chave se o campo estiver vazio;
  • retorna sem lançar erro quando o acesso ao armazenamento falha.

O método clearAllStorage() remove as chaves dos três serviços.
