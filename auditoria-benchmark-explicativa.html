LAUDO DE AUDITORIA TÉCNICA E MATEMÁTICA DO BENCHMARK

Diagnóstico explicativo do módulo de comparação financeira

Componentes auditados: BenchmarkChart.jsx, server.mjs e integração Vite/BCB

Séries: CDI 4392 e Poupança 196

Documento consolidado para impressão e exportação em PDF

1. Sumário Executivo

O módulo de Benchmark consulta as séries 4392 e 196 do Banco Central por meio do endpoint local /api/bcb. O backend valida as séries, encaminha a consulta ao SGS/BCB, remove duplicidades e devolve os dados ao frontend.

O diagnóstico identificou três causas distintas para o comportamento visual observado:

  1. A Poupança é acumulada corretamente como fator, mas é exibida como fator * 100, fazendo o primeiro ponto aparecer próximo de 100% em vez de aproximadamente 0,67%.
  2. O eixo Y é dimensionado pela Poupança artificialmente elevada, comprimindo as variações do CDI e fazendo as linhas parecerem retas.
  3. A data atual é adicionada mesmo sem observação do BCB, criando um ponto em que CDI e Poupança ficam nulos e somente a carteira possui valor.
Conclusão executiva: o backend está entregando dados mensais válidos e ordenados. A falha principal está na conversão do acumulado da Poupança para percentual, seguida pelo desalinhamento visual provocado pela injeção da data atual.

2. Arquitetura e Fluxo de Dados

DashboardPage.jsx
  -> BenchmarkChart.jsx
  -> /api/bcb via proxy Vite
  -> server.mjs
  -> API SGS/BCB
  -> parse das séries
  -> montagem de chartData
  -> Recharts

O Dashboard envia ao componente os totais atuais da carteira, especialmente totals.patrimonio e totals.investido. O componente solicita uma janela aproximada de 12 meses, começando no primeiro dia do mês de referência e terminando na data atual.

O Vite encaminha /api para http://127.0.0.1:3001. O backend usa a URL-base:

https://api.bcb.gov.br/dados/serie/bcdata.sgs.{serie}/dados

4. Diagnóstico da Poupança no Topo do Gráfico

O componente inicia o fator acumulado em:

let savingsAccumulated = 1;

A capitalização mensal é:

savingsAccumulated *= 1 + (savingsRate / 100);

Essa operação está correta para formar o fator acumulado. O erro está na saída:

point.poupanca = Number((savingsAccumulated * 100).toFixed(4));

O número 1 representa 100% do capital original. Ele não representa 100% de rentabilidade. Com uma taxa de 0,6751%:

fator acumulado = 1,006751
saída atual = 1,006751 * 100 = 100,6751%
retorno correto = (1,006751 - 1) * 100 = 0,6751%

Assim, a série começa artificialmente na faixa de 100%. Depois de vários meses, continua na faixa de 100% a 110%, embora o retorno real acumulado esteja na faixa aproximada de 0% a 10%.

5. Diagnóstico das Linhas Retas ou Chapadas

O eixo Y é calculado com o maior valor de todas as séries:

const yMax = Math.max(
  1,
  Math.ceil(Math.max(...yValues, 0) * 1.1 / 5) * 5
);

Como a Poupança está em torno de 100%, o eixo pode chegar a aproximadamente 115%. Nesse intervalo:

  • CDI entre aproximadamente 13,90% e 14,90% ocupa uma faixa pequena;
  • as alterações mensais do CDI ficam visualmente comprimidas;
  • a Poupança parece uma linha alta e pouco informativa;
  • a percepção é de linhas retas ou estáticas, apesar de existirem variações nos dados.

A série CDI 4392 também possui valores iguais por alguns meses. Isso contribui para trechos horizontais, mas não há evidência de que o cdiMap esteja repetindo todos os valores artificialmente.

6. Diagnóstico do Mapeamento e das Datas

O mapeamento do CDI é:

const cdiByDate = new Map(cdi.map((item) => [item.date, item.rate]));

O mapeamento da Poupança é:

const savingsByDate = new Map(poupanca.map((item) => [item.date, item.rate]));

Como as datas são convertidas para o formato ISO yyyy-MM-dd, a ordenação textual é cronologicamente válida.

A união é montada com:

const dates = Array.from(new Set([
  ...cdiByDate.keys(),
  ...savingsByDate.keys(),
  end
])).filter((date) => date >= start && date <= end).sort();

As séries BCB terminam no dia 01 do mês. O código adiciona ainda a data atual, por exemplo:

01/09/2026 -> dados BCB disponíveis
14/09/2026 -> apenas carteira, CDI null, Poupança null

Com connectNulls={false}, CDI e Poupança terminam antes do ponto final da carteira. Isso cria uma quebra visual, mas não é a causa da Poupança subir para o topo.

7. CDI: Regra Atual e Limitação

O CDI 4392 é colocado diretamente no ponto correspondente:

cdi: cdiByDate.has(date)
  ? Number(cdiByDate.get(date).toFixed(4))
  : null

Não há acumulação manual do CDI no frontend. Isso é coerente com a interpretação adotada de que a série já representa um valor anualizado. O código, entretanto, não implementa um calendário explícito de dias úteis, feriados, convenção de 252 dias ou reconstrução diária.

Portanto, o componente não calcula o CDI oficial diário do zero. Ele exibe diretamente o valor retornado pela série 4392 nas datas mensais disponíveis. A confiabilidade depende da semântica oficial dessa série e da unidade do valor recebido.

8. Carteira

A carteira é calculada por:

portfolioReturn = invested > 0
  ? ((patrimony / invested) - 1) * 100
  : 0;

Ela só recebe valor na data final:

carteira: date === end ? portfolioReturn : null

Não existe histórico retroativo de patrimônio no componente. Não há interpolação linear, snapshots históricos, preços históricos, retorno ponderado no tempo, retorno ponderado por dinheiro ou recomposição histórica de dividendos.

Risco de interpretação: o eixo cobre 12 meses, mas a carteira possui apenas um ponto atual. O gráfico pode sugerir evolução histórica onde existe somente uma observação final.

9. Tratamento de Falhas

As consultas são feitas com Promise.allSettled. Se uma série falha, ela vira um array vazio e a outra pode continuar sendo exibida.

O backend retorna:

  • HTTP 400 para série não permitida ou datas inválidas;
  • HTTP 502 quando o BCB falha ou retorna vazio;
  • HTTP 200 com os dados válidos.

O frontend exibe aviso quando CDI ou Poupança ficam indisponíveis. Não existe fallback numérico fictício de 0,85% ou 0,50% no código atual auditado.

11. Conclusão

O endpoint do backend não é a origem principal das anomalias. Ele fornece dados mensais válidos e ordenados para as séries 4392 e 196.

A causa principal da escala incorreta é a conversão da Poupança acumulada:

errado:  savingsAccumulated * 100
correto: (savingsAccumulated - 1) * 100

A causa da aparência chapada é a combinação entre o erro de escala da Poupança e as pequenas variações do CDI em relação ao eixo inflado.

A causa do buraco no final é a inclusão da data atual sem observações BCB, somada a connectNulls={false}.

Parecer final: o módulo é funcional como gráfico aproximado, mas apresenta um erro matemático objetivo na série da Poupança e uma limitação visual de alinhamento no ponto atual. A carteira não representa histórico de 12 meses; representa somente o retorno atual calculado a partir de patrimônio e total investido.
